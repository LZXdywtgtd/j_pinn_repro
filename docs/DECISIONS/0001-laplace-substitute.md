## 1. 背景

J-PINN 论文（Materials & Design 2026, `j.matdes.2026.116567`）解决 2D 含裂纹弹性力学：
- 域：物理 DCB 试件（a₀=40mm, W=25mm, B=4mm）
- PDE：Navier-Cauchy 平衡方程（论文 §2.1 Eq.7）
- 本构：Hooke 律（λ=27070, μ=27481 MPa，铝）
- 输出：位移场 u₁(x,y), u₂(x,y)
- 数据：原论文实验 DIC 测得全场位移

团队**没有**论文原版 DIC 数据；持有 COMSOL 2D 温度场仿真数据。

---

## 2. 决策原话（来自用户首个任务提示词 `jsonl:3`）

> 因缺少原论文 DIC 数据，我们采用**降维策略**：不直接跑断裂力学，而是用论文的 **"4 区域神经网络架构 + 物理信息损失（PDE Loss）+ 区域缝合（Interface Loss）"**，去拟合一个 2D 热力学场（模仿 COMSOL 输出的温度场 T）。这既能证明框架可迁移，也能与我们有 COMSOL 数据的现状完美契合。

---

## 3. 决策内容（维度简化映射）

| 维度 | 论文 | 本项目（v0.5 起） |
|---|---|---|
| **PDE** | Navier-Cauchy 平衡方程（λ+μ tr(ε)δ + 2μ ε） | **Laplace ∇²T=0**（无 λ/μ） |
| **域** | DCB 物理试件（mm 单位） | **[-1, 1]² 归一化** |
| **输出** | 位移场 (u, v) | **标量温度场 T(x, y)** |
| **数据** | 实验 DIC 测全场位移 | **合成 log 调和场 + COMSOL 温度场** |
| **裂纹** | 真不连续（撕裂） | **tanh(50y) 平滑** |
| **J-integral 物理意义** | 应变能释放率 G_I（断裂力学） | **路径无关性算法验证** |

**保留的论文架构贡献**（论文 §3.2-3.3）：
- 4 区域分解（JPINN + TwoRegion + SingleRegion 三个变体）
- PDE 残差监督（PDE Loss）
- 接口缝合损失（Interface Loss + L_traction）
- 外边界 Dirichlet 条件（BC Loss）
- Sobolev Hessian 正则（可选 Smoothness）
- Huber 抗噪 + Z-score 边界去噪（论文 §3.3 Eq.19-20）

## 4. 备选方案 + 否决理由

| 备选 | 状态 | 否决理由 |
|---|---|---|
| **完整 Navier-Cauchy + DCB** | 拒绝 | 无 DIC 数据；训练需真实全场位移监督；论文 PDE 含混合二阶导量级 ~10⁴ 训练不稳定 |
| **实验 DIC 反演** | 拒绝 | 数据未持有；无法端到端验证 |
| **有限元（FEM）数据** | 拒绝 | 团队无 30×30 DCB 网格 FEM 导出 |
| **GPU 训练** | 拒绝 | 论文明示 ~72K 参数下 CPU 10× faster than GPU（§4.5） |
| **NTK 自动权重** | 拒绝 | 论文自己结论"不稳定"（§3.4），手动量级分析 |
| **直接做 COMSOL PNG → 拟合** | 接受（v0.5 已做） | COMSOL 团队有 2D 温度场可做交叉验证 |

## 5. 反转条件

本决策**可反转**，需要：

1. **数据**：获得论文原版 DIC 全场位移数据 或 公开 DCB 试件 FEM 基准（30×30 网格）
2. **代码工作量**：~500-800 LOC（换 PDE、换 BC、换本构、换域）
3. **重写 Loss**：恢复 Navier-Cauchy 的混合二阶导项 + Lamé 参数
4. **重训**：论文 20K epoch，CPU ~58 min（已记录于 docs/experiment_reports/项目算法与训练实验设计报告.md §3.2）
5. **验证**：对标论文 Table 3 G_I 1.51% 误差

## 8. 反思

降维决策是**清醒而负责任的科学实践**：
- 不是"做不出来就简化"的退路，是有明确物理对应（热传导 ↔ 弹性力学的 PDE 残差监督框架）
- 不是"偷懒"，而是用最少的代码保留论文最核心的架构贡献（4 区域 + PDE + Interface）
- 风险全部文档化（LossWeights 量级偏差、Mode I/II 物理意义、J=0 基线）

当未来反转条件满足时，本 ADR 应被替换为 ADR-0002（Navier-Cauchy 切换）。

| 考量维度 | 当时判断 |
|---|---|
| **数据可达性** | 只有 COMSOL 2D 温度场可做验证；缺全场位移 |
| **物理对应性** | 4 区域 + PDE 残差 + 缝合框架与具体 PDE 类型解耦；Laplace 是最简单的 PDE 算子 |
| **学术价值** | "证明框架可迁移性"优先于"完整复现" |
| **工作量** | Laplace 实现 ~200 LOC vs Navier-Cauchy ~600 LOC（混合二阶导 + Lamé 参数 + 真实 BC）|
| **训练稳定性** | Laplace PDE 量级稳定；Navier-Cauchy 含混合二阶导量级 ~10⁴ 训练难 |
| **COMSOL 交叉验证** | 温度场可直接与 COMSOL PNG 对比（v0.5 已落地 load_comsol_png）|
| **风险** | 维度简化后无法复现论文 Table 3 G_I 数值（仅路径无关性可验证）|

### 9.4 当时的反向声音（已被压倒）

- "应该完整复现，否则没意义" → 反驳：完整复现需要数据 + 算力 + 时间；当前资源不支持
- "Laplace 太简单，体现不出论文的复杂性" → 反驳：复杂度在架构（4 区域 + 缝合 + BC），不在 PDE 算子
- "应该用 Burgers 方程替代 Navier-Cauchy" → 反驳：与 COMSOL 数据无直接对应；温度场更自然

## 10. 局限性（必须记录）

### 10.1 当前实现的局限

1. **J-integral 无物理意义**：热场下 Mode I/II 分解只是形式验证；无法复现论文 Table 3 G_I=3.99756 vs FEM 3.93824
2. **Mode I/II 概念错位**：论文 Mode I = 法向位移 + 切向零应力；本项目 Mode I/II = 裂纹面对称/反对称分解（无物理意义）
3. **BC loss 默认值需要上下文**：合成数据用 MSE（论文 Eq.18）；真实数据用 Huber（论文 Eq.19）
4. **损失权重量级偏差**：论文 Table 2 L_pde=1e-6；本项目 λ_pde=100（量级完全反）
5. **裂纹段启发式**：tanh(50y) 平滑是数学替代物，**无物理对应**（真裂纹场不连续）
6. **域大小归一化**：[-1,1]² 抹去物理单位（mm vs 归一化）
7. **Sobolev smoothness 单分量**：论文 u+v 双重求和；本项目仅 T
8. **初始化未指定**：依赖 PyTorch 默认 Kaiming uniform；论文沉默

### 10.2 论文 vs 本项目的"真伪"边界

| 论文宣称 | 本项目状态 |
|---|---|
| 4 区域分解架构 | ✅ 完整复现 |
| PDE 残差监督 | ⚠️ 算法等价，物理不对应 |
| 接口缝合 | ✅ 算法等价 |
| BC Huber + Z-score 去噪 | ✅ 算法等价 |
| Mode I/II 分解 | ⚠️ 形式实现，无物理意义 |
| J-integral 路径无关性 | ⚠️ 数学正确但 J=0 基线 |
| G_I=3.99756 N/mm | ❌ 数据缺口，无法复现 |
| 20K epoch 训练 | ⚠️ 5K（合成场收敛够）|
| CPU 10× faster than GPU | ✅ 直接采纳 |

## 11. 冲突检测与重新决策机制

### 11.1 何时应触发"重新评估本决策"

如果遇到以下任一情况，**必须**重新审视本 ADR：

1. **数据变化**：获得论文原版 DIC 数据 / 公开 DCB FEM 基准 / 自有 COMSOL 跑出弹性仿真
2. **目标变化**：用户原话从"框架可迁移性"变成"完整复现 / 发表"
3. **资源变化**：算力充足 + 时间宽裕
4. **物理意义质疑**：发现热场 J-integral 与论文 Mode I/II 对比被误读 / 实验方有反馈
5. **学术方要求**：投稿 / 答辩要求对标论文 Table 3
6. **架构缺陷**：发现 4 区域框架在某场景失效且降维掩盖问题

### 11.2 重新决策流程

触发上述任一条件时：
1. **重新评估 ADR-0001**：本文件是否仍成立？
2. **如不成立**：创建 ADR-0002（Navier-Cauchy 切换）+ 新增对应 commit
3. **如部分成立**：更新本文件（在"决策状态"中标注"已部分反转"，不在 v0.7 阶段 0 基础上新建）
4. **如仍成立**：在文档底部追加"复核记录"段，不修改原有决策

### 11.3 不能死照蛮干

ADR 是**参考，不是枷锁**。具体场景：

| 场景 | 行动 |
|---|---|
| 用户要求完整复现论文 | 触发 ADR 重新评估 |
| 数据状态变化 | 触发 ADR 重新评估 |
| 学术答辩/投稿需要论文数值 | 触发 ADR 重新评估 |
| 内部 PoC 验证、框架迁移 | 维持当前 ADR |
| COMSOL 交叉验证、温度场应用 | 维持当前 ADR |
| 单纯实现细节调整（不改变 PDE 类型）| 维持当前 ADR |
