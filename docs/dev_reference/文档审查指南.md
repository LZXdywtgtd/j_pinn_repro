## 三、通用审查维度

### 3.1 准确性审查（最重要）

**核心原则**：文档必须与实际代码一致。

#### 必查项

| 检查项 | 审查方法 |
|--------|----------|
| CLI 参数是否存在 | `grep -n "add_argument" train.py` |
| 函数签名是否正确 | `python -c "import inspect; from models.pinn_core import JPINN; print(inspect.signature(JPINN))"` |
| 默认参数值是否正确 | 检查源代码中的默认值 |
| 函数/类名是否正确 | 对照 `models/` `losses/` `utils.py` 源文件 |
| 损失权重默认值是否正确 | 检查 `losses.py` 中的 `LossWeights` |
| 参数量是否正确 | `python -c "from models.pinn_core import JPINN; print(JPINN().count_parameters())"` |

#### 常见错误模式

- ❌ 文档写了 `--use_se` 但实际只有 `--use_coord_attn`
- ❌ 文档写了 `patience=20` 但实际默认 `patience=30`
- ❌ 文档写了 `lr=3e-4` 但实际默认 `lr=1e-3`
- ❌ 描述了不存在的函数/类
- ❌ MLPBlock 写 `n_layers` 但实际是 `n_hidden_layers`

#### 验证命令

```bash
# 验证参数存在
grep -n "add_argument" train.py

# 验证函数签名
python -c "import inspect; from models.pinn_core import MLPBlock; print(inspect.signature(MLPBlock.__init__))"

# 验证模型架构
python -c "from models.pinn_core import JPINN; print(JPINN().count_parameters())"
```

### 3.3 一致性审查

#### 跨文档一致性

同一信息在多个文档中出现时，必须保持一致：

| 必查一致性项 | 涉及文档 |
|------------|----------|
| `--epochs` 默认 5000 | 快速配置指南、调参指南、开发人员文档 |
| `--lr` 默认 1e-3 | 同上 |
| 参数量 70,148 | 架构设计文档、调参指南、API 文档 |
| `lambda_pde` 默认 100 | 架构设计文档、调参指南、API 文档 |
| `n_int_per_region` 默认 2500 | API 文档、调参指南 |
| 训练时长 ~64 min | 架构设计文档、算法报告 |

#### 跨文档一致性脚本

```python
import os, re
keywords = ['1e-3', '70,148', '5000', 'lambda_pde', 'checkpoints/']
for root, _, files in os.walk('docs'):
    for f in files:
        if f.endswith('.md'):
            path = os.path.join(root, f)
            with open(path, 'r', encoding='utf-8') as fp:
                content = fp.read()
            for kw in keywords:
                if re.search(kw, content):
                    for ln, line in enumerate(content.splitlines(), 1):
                        if re.search(kw, line):
                            print(f'{path}:{ln}: {line.strip()[:120]}')
```

## 五、审查流程

### Step 1：代码审查

修改代码后，先确认需要更新的文档：
1. 新增/修改了 CLI 参数 → 更新用户指南、调参文档、开发人员文档
2. 新增/修改了模型架构 → 更新架构设计文档
3. 新增/修改了损失函数 → 更新架构设计文档、调参文档
4. 新增/修改了公开函数 → 更新 API 文档
5. 新增 bug → 更新 CODE_BUGS.md

### Step 2：文档自检

按照本指南 §三 通用审查维度逐项检查。

### Step 3：交叉引用验证

```python
import os, re
for root, _, files in os.walk('docs'):
    for f in files:
        if f.endswith('.md'):
            path = os.path.join(root, f)
            with open(path, 'r', encoding='utf-8') as fp:
                content = fp.read()
            for link in re.findall(r'\]\(([^)]+\.md)\)', content):
                base = os.path.dirname(path)
                target = os.path.normpath(os.path.join(base, link))
                if not os.path.exists(target):
                    print(f'BROKEN: {path} -> {link}')
```

### Step 4：运行示例

```bash
# 用户指南命令示例
python train.py --epochs 10  # 短训冒烟

# API 文档函数验证
python -c "
import inspect
from models.pinn_core import MLPBlock
print(inspect.signature(MLPBlock.__init__))
"
```

## 六、常见问题速查

| 文档问题 | 根因 | 解决方案 |
|----------|------|----------|
| 参数不存在 | 文档基于旧版代码 | 对照 `train.py` 重新确认 |
| 默认值不对 | 未同步最新默认值 | 从源代码读取实际默认值 |
| 链接断裂 | 文件重命名后未更新引用 | 用 grep 搜索旧文件名并替换 |
| 架构描述不一致 | 不同文档由不同人维护 | 以架构设计文档为准，其他文档引用 |
| 缺少新增内容 | 审查时未对照源代码 | 必须阅读源代码后再审查 |
| `MLPBlock.n_layers` 错 | n_layers 语义混淆 | 改为 `n_hidden_layers=4` |
| 损失权重不一致 | 各文档手动维护 | 以 `losses.LossWeights` dataclass 为准 |
