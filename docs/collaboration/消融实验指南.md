# 消融实验编排指南

> J-PINN 多 ablation 自动训练与对比 | 版本 0.2

本指南说明如何用 `run_ablations.py` 一键跑完 3 个消融实验（single / two / full），并自动生成对比图。

---

## 一、为什么需要编排器

J-PINN 的核心论点（论文 §4.6）需要**公平对比** 1/2/4 区域消融才能验证。`run_ablations.py` 把"手动跑 3 次 + 手动跑 visualize"流程自动化：

- 集中管理 ablation 配方（JSON 文件）
- 自动按依赖排序
- 依次启动 `train.py` 子进程（非阻塞 Ctrl-C）
- 完成后自动调 `visualize.py` 生成 `ablation_compare.png`

---

## 二、快速上手

### 2.1 一键跑全部 3 个 ablation

```bash
conda activate jpinn
cd /d D:/team_project/j_pinn_repro
python run_ablations.py
```

**预计总时长（CPU）**：~4.5 小时
- `ablation-single-v0.2`：~155 min
- `ablation-two-v0.2`：~55 min
- `ablation-full-v0.2`：~65 min

**输出**（v0.9：自动归档；编排器不再在配方里写死 `--out`/`--log`，子进程统一加 `--force`）：
- `outputs/{single,two,full}/<task_id>/`：model_best.pt + train_history.csv + config.json + metadata.json（本地产物，不入仓）
- `outputs/latest.json`：每个 ablation 的最新 task_id 指针
- `logs/figures/ablation_compare.png`（本地产物；对比图由编排器收集 latest.json 指向的 checkpoint 生成）

### 2.2 只跑一个

```bash
python run_ablations.py --only ablation-full-v0.2
```

### 2.3 dry-run（看计划不执行）

```bash
python run_ablations.py --dry-run
```

输出：
```
将依次执行 3 个 ablation：
  1. [ablation-single-v0.2] 单区域 PINN（论文 §4.6 baseline） → outputs/single/<task_id>/
  2. [ablation-two-v0.2] 上下分割 2 区域（论文 §4.6 中间基线） → outputs/two/<task_id>/
  3. [ablation-full-v0.2] 4 区域 J-PINN（论文主模型） → outputs/full/<task_id>/

总预计时长（CPU）：单 ~155 min + 双 ~55 min + 4 区域 ~65 min ≈ 4.5 小时
```

### 2.4 只生成对比图（已有 checkpoint）

```bash
python run_ablations.py --visualize-only
```

跳过训练，直接从 `outputs/latest.json` 解析各 ablation 的最新 checkpoint（旧式显式路径作为兜底），生成 `ablation_compare.png`。

### 2.5 追加 CLI 参数

```bash
python run_ablations.py --extra-args --seed 123
```

把 `--seed 123` 附加到每个 ablation 的 `train.py` 调用末尾。

## 三、配方表 schema（`tasks/ablation_recipes.json`）

v0.9 起配方**不再包含 `--out`/`--log` 键**：编排器会传给子进程 `--force`，裸 train.py 自动归档到 `outputs/<ablation>/<task_id>/`（各 ablation 互不覆盖）：

```json
{
  "_schema": "[{id, name, args, description, expected_n_params, depends_on}]",
  "tasks": [
    {
      "id": "ablation-full-v0.2",
      "name": "4 区域 J-PINN（论文主模型）",
      "args": {
        "--ablation": "full",
        "--epochs": 5000
      },
      "description": "4 个独立 MLP（论文保形）；论文预期 E₂ 最低（0.91%）",
      "expected_n_params": 70148,
      "depends_on": []
    }
  ]
}
```

> 旧配方若仍含 `--out`/`--log`，train.py 仍按显式路径处理，但子进程已统一加 `--force`（防重复批跑被显式路径守卫卡住）。

### 字段说明

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `id` | str | ✓ | 唯一标识（用于 `--only`） |
| `name` | str | ✓ | 人类可读名称 |
| `args` | dict | ✓ | 传给 `train.py` 的参数（key 必须以 `--` 开头） |
| `description` | str | - | ablation 简介（dry-run 时显示） |
| `expected_n_params` | int | - | 预期参数量（v0.2 公平性断言参考） |
| `depends_on` | list[str] | - | 依赖的其他 task_id（拓扑排序用） |

## 四、添加新 ablation

例：增加"无缝合约束"的对照组（`lambda_interface=0`）。

1. 编辑 `tasks/ablation_recipes.json`，加新条目（v0.9：不带 `--out`/`--log`，输出自动归档）：
   ```json
   {
     "id": "ablation-full-no-stitching",
     "name": "4 区域 + 无缝合约束（消融）",
     "args": {
       "--ablation": "full",
       "--epochs": 5000,
       "--lambda_interface": "0.0",
       "--lambda_interface_normal": "0.0"
     },
     "description": "4 区域但 lambda_interface=0；论文 §4.6 第 5 行预期 E₂ 高",
     "expected_n_params": 70148,
     "depends_on": []
   }
   ```

2. dry-run 验证：
   ```bash
   python run_ablations.py --dry-run
   ```

3. 跑该 ablation：
   ```bash
   python run_ablations.py --only ablation-full-no-stitching
   ```

4. 重新生成对比图（含新 ablation）：
   ```bash
   python run_ablations.py --visualize-only
   ```

## 五、设计决策与限制

| 决策 | 选择 | 理由 |
|---|---|---|
| 进程模型 | subprocess.run（非 os.system） | v4 v4.6.10 修复 Windows cmd 转义 bug |
| 并发 | 单进程串行 | CPU 训练，独占算力；并行无意义 |
| 中断 | Ctrl-C 透传到子进程（不保存中间状态）| 简单；如需 resume 见 P4（待做） |
| 配方 schema | 仿 v4 tasks/team_baseline.json | 一致性，便于将来与 v4 工具链互通 |
| 输出 | v0.9：自动归档 `outputs/<ablation>/<task_id>/`；编排器给子进程统一加 `--force` | train.py 显式路径（旧方式）仍兼容 |

## 六、与 v4 team_train.py 的差异

| 项 | v4 team_train.py | 本项目 run_ablations.py |
|---|---|---|
| 调度模型 | 拓扑排序 + 多 GPU 拓扑感知 | 简化：仅串行 + 单 CPU |
| 配方 schema | JSON 任务列表 + 依赖图 + L2/L3 等级 | 简化：JSON 列表 + `depends_on` 字段 |
| 失败恢复 | 检查点 + 续训（v4.6.11+） | 当前不支持（v0.2 P5 范围外） |
| 任务 ID 解析 | 模糊匹配（v4.6.11 fuzzy match） | 严格匹配 `--only` |
| GPU 调度 | 自动 detect 显存 / L2+ 同级 | 不需要（论文 CPU 更快） |
